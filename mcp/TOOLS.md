# aegis-mcp 工具清单

## admins（20）

| `admins_delegations` | 读 | 权限委托记录。 |
| `admins_delete_role` | 危险 | 删除自定义角色（持有者随即失去其权限）。 |
| `admins_explain` | 写 | 解释「某管理员在某作用域下能不能做某事、为什么」——排查 403 的首选。 |
| `admins_grant_temp_permission` | 写 | 授予临时权限，到期自动失效。 |
| `admins_list` | 读 | 管理员列表（含角色分配、状态、最近登录），或当前在线管理员。 |

| `admins_set_status` | 危险 | 启用或停用管理员账号。 |

## cardkey（20）

卡密：批次生成 / 导入 / 补发 / 提卡 / 启停 / 删除、单卡调整与作废恢复、设备解绑、管理员代兑、核销记录、统计与目录。

| 工具 | 类别 | 说明 |
|---|---|---|
| `cardkey_append` | 写 | 按原批次的前缀、段数、字符集再生成 N 张卡（批次总数随之增加）。导入的批次没有格式，不能补发。 |
| `cardkey_batch` | 读 | 单个批次的完整配置与进度。 |
| `cardkey_batches` | 读 | 卡密批次列表（随行带核销进度：总数、未用、已用、作废、过期、已提取）。 |
| `cardkey_catalog` | 读 | 卡密表单目录：权益类型与取值形态、卡面字符集、有效期模式、领取对象、可选套餐与功能标识。生成批次前先看它。 |
| `cardkey_delete` | 危险 | 删除选中的卡（不可恢复）。只删从没被用过的卡，用过的自动跳过（返回 skipped）。先向用户确认。 |
| `cardkey_delete_batch` | 危险 | 删除批次及其全部卡（不可恢复）。只能删从没被用过的批次（否则 40982，请改为停用）。先向用户确认。 |
| `cardkey_disable` | 危险 | 作废选中的卡（作废后不能兑换 / 登录，已核销的卡不参与）。可用 cardkey_restore 恢复，但作废期间用户会被拒绝。先确认。 |
| `cardkey_distribute` | 写 | 手动标记 / 取消选中卡的「已提取」状态（不改变卡能否使用）。 |
| `cardkey_extract` | 写 | 提卡：取出 N 张未使用、未提取、未过期的卡并标记为已提取，卡面随结果返回（交给渠道）。卡面是可兑换的凭证，注意保密。 |
| `cardkey_generate` | 写 | 生成一批卡密，或给 codes 导入已有卡面。生成后的卡立即可用（批次默认启用），用 cardkey_extract 取卡面交给渠道。 |
| `cardkey_get` | 读 | 单张卡密的详情（所属批次、权益、绑定用户、核销记录），可附带绑定设备列表。 |
| `cardkey_list` | 读 | 卡密列表（卡面、状态、使用次数、绑定用户、到期时间、是否已提取）。 |
| `cardkey_redeem` | 写 | 管理员代兑：替一个用户核销一张卡并发放权益（来源记为 admin，发站内信）。核销后不能撤回，先确认卡面与用户。 |
| `cardkey_redemptions` | 读 | 核销记录（谁在何时用哪张卡领了什么，含发放结果快照）。 |
| `cardkey_restore` | 写 | 恢复被作废的卡，使其重新可用。 |
| `cardkey_set_batch_status` | 写 | 启用 / 停用整个批次（停用后整批不能兑换或登录，单卡状态不变，可随时恢复）。 |
| `cardkey_stats` | 读 | 卡密统计：总量、可用、已提取、有效授权、面值（发出 / 已用）、按天核销趋势、来源分布与热门批次。 |
| `cardkey_unbind_devices` | 危险 | 解绑授权卡上的一台设备，或清空全部设备，把名额还回去（被解绑的设备下次登录需要重新占位）。先向用户确认。 |
| `cardkey_update` | 写 | 调整单张卡：备注、可绑设备数、到期时间。只传要改的字段。 |
| `cardkey_update_batch` | 写 | 修改批次（卡面格式、形态、有效期模式、单卡设备数不能改）。只传要改的字段：后端整体覆盖，这里先读批次再合并。 |

## core（4）

通用层：凭证自述、接口目录、参数说明、任意管理端接口调用。

| 工具 | 类别 | 说明 |
|---|---|---|
| `call_api` | 危险 | 直接调用任意一条 Aegis 管理端接口（通用出口）。先用 list_endpoints / describe_endpoint 确认路径与参数。写操作真实生效并记审计；不可逆操作前先征得用户确认。 |
| `describe_endpoint` | 读 | 一条管理端接口的参数说明：路径参数、查询参数、请求体字段（类型、枚举、必填带 *）、所需权限点，以及当前密钥能否调用。 |
| `list_endpoints` | 读 | 在 Aegis 管理端全部接口里查找（约 970 条）。每条带方法、路径模板、处理函数名、分组、所需权限点、是否按应用鉴权，以及当前密钥能不能调和原因。没有现成工具时用它，再用 describe_endpoint 看参数。 |
| `whoami` | 读 | 当前凭证代表哪个管理员、密钥的权限范围 / 应用范围 / 是否只读、生效权限点与可访问的应用列表。开始任何操作前先调用一次。 |

## egress（46）

出海网关：总览与运行态、画布（读、按名字增改节点与连线、校验、导入导出、应用、版本回滚）、路由解释与 TCP / UDP 自测、

| 工具 | 类别 | 说明 |
|---|---|---|
| `egress_add_rule` | 写 | 在规则链上新增一条网关路由规则并保存草稿（线上不变）。规则自上而下匹配，同一条规则内不同条件「同时满足」、同一条件多项「任一」。 |
| `egress_apply` | 危险 | 把当前草稿应用到线上：编译 → mihomo 核心校验并热重载（缺核心会先自动下载）→ 网关热替换路由表 → 记一个新版本。 |
| `egress_catalog` | 读 | 画布目录（按段取，避免一次返回过大）：节点类型与端口能连什么、网关协议与 UDP 承载方式、mihomo 各协议的字段（键、类型、选项、默认值、何时显示）、 |
| `egress_connect` | 写 | 在两个节点之间加一条连线并保存草稿（规则命中去向、网关未命中去向、线路经由、策略组成员、前置代理）。 |
| `egress_core_close_connections` | 危险 | 关闭经 mihomo 的一条或全部在途连接，调用方会收到连接错误并按各自策略重试。 |
| `egress_core_connections` | 读 | 经 mihomo 的在途连接：目标（域名或 IP:端口）、网络、经过的线路链、命中的核心规则、上下行字节、开始时间；附累计流量与内存。 |
| `egress_core_delay` | 写 | 经核心测延迟（毫秒，0 为超时）。结果会写进核心的延迟历史，url-test / fallback 组据此选路。 |
| `egress_core_dns` | 写 | 经 mihomo 的 DNS 模块解析（核心 DNS 关闭时走系统解析），用来排查节点域名解析或 DNS 污染。 |
| `egress_core_install` | 写 | 安装或升级 mihomo 核心：从 GitHub 发布页下载本机平台的包（镜像优先）并校验 sha256，装好后已有配置会自动重启核心。 |
| `egress_core_logs` | 读 | 核心日志（最近 2000 行）：核心自己的输出，以及网关托管核心时记下的事件（source=aegis：启动、热重载、安装、自动拉起、端口冲突）。 |
| `egress_core_maintenance` | 写 | 核心维护：重新下载 GeoIP / GeoSite 数据库，或清空 DNS 缓存。 |

## wallet（5）

钱包：用户余额与流水、应用级资金流水与统计、管理员调整余额、把流水凭证寄到邮箱。

| 工具 | 类别 | 说明 |
|---|---|---|
| `wallet_adjust` | 危险 | 管理员调整用户钱包余额（类型 admin_adjust，立即生效，余额不足时扣减被拒绝）。 |
| `wallet_email_receipt` | 写 | 把一笔钱包流水的 PDF 凭证寄到指定邮箱（客服代开、对账留档）。邮件发出后无法撤回，先确认收件地址。 |
| `wallet_get` | 读 | 某用户的钱包：余额、冻结金额、累计充值与累计消费，可附带该用户的流水分页。需要 app:user:read。 |
| `wallet_stats` | 读 | 应用资金面板：时间窗内的入账 / 出账汇总、按类型分布、余额总量。 |
| `wallet_transactions` | 读 | 按应用查钱包流水（全部用户的资金往来），可按用户、类型、方向、关键词、时间窗筛选。时间也接受 YYYY-MM-DD 或 Unix 秒。 |
