# 订单实付与待人工处理

## 起因

爱发电渠道用「自选金额」下单：链接里带着订单金额（`custom_price`），但付款人在爱发电的付款页上**可以改金额**。
2026-10-14 至 11-08 有 8 笔永久会员订单（49.90 / 49.99）被付款人改成了 50.00（7 笔）或 49.00（1 笔）。
结单要求实付等于订单金额，于是全部被拒、订单过期，管理员逐笔手动补发了会员和赠送积分；
被拒的订单在 24 小时内每 2 分钟查一次单，每次都写一条回调日志（一笔就是两百多条，8 笔共 5245 条）。
同期按 49.90 正常付款的有 112 笔，说明爱发电本身不改金额。

## 现在的规则（`applyVerifiedResult`，迁移 000150）

| 情况 | 处理 |
|---|---|
| 实付 = 订单金额 | 照常结单，`paid_amount` 记订单金额 |
| 实付 > 订单金额，且渠道的付款人能改金额（目前只有爱发电） | 照常结单、照常发货；`paid_amount` 记实付，另记一条 `overpaid` 回调日志写明多付多少 |
| 实付 < 订单金额，或付款人改不了金额的渠道金额对不上 | 不结单；订单标成**待人工处理**（`review_reason = amount_mismatch`，记下实付与说明），之后不再自动查单补单；给该应用的管理员与超级管理员各发一条站内信（同一笔订单只发一次） |

- 渠道能力是可选接口 `payerAdjustableAmount`（`service/payment_review.go`），爱发电实现它。别的渠道金额改不了，
  对不上说明有问题（配置错、渠道异常、伪造），继续严格相等。
- 退款仍按订单金额计算；多付的差额要退给用户时在渠道后台处理。
- 待人工处理的订单如果之后又收到金额正确的推送（付款人重新付了一次），照常结单。
- 迁移 000150 给已经因金额不一致被拒过的未结订单补记了标记与实付（线上就是上面那 8 笔），不发通知：它们当时已经手动处理过。

## 字段

`payment_orders.paid_amount`（渠道实付）、`review_reason`、`review_note`、`review_at`；订单 JSON 里对应
`paid_amount`、`review_reason`、`review_note`、`review_at`（为空时不出现）。

控制台「商业 → 订单」：
- 列表的金额下面在实付与订单金额不同时显示「实付 50.00」（多付绿色、少付琥珀色，悬停看多付或少付多少），
  状态下面显示「待人工处理」；状态筛选里有「待人工处理」（后端 `status=review`，不是订单状态，按 `review_reason` 筛）。
- 详情的金额下面写明实付与差额，待人工处理的订单在顶部有一块说明（原因、标记时间、该怎么处理），订单信息里多一行「实付金额」。
- 站内信里带着订单号与两边的金额，点开跳到「商业 → 订单」。

## 验证

`TestAfdianPaymentIntegration`：少付标成待人工处理并记下实付、后台补单与用户查单都不再打上游、重推仍拒绝且只通知一次、
多付照常结单并记 `overpaid` 日志、正常结单的实付等于订单金额、「待人工处理」筛选只返回少付的那一笔、别的渠道不允许多付。
